# Uji manual oleh pengguna

Panduan ini belum dijalankan oleh agent. Pakai profil **development**, bukan production. Tutup koneksi Pritunl untuk profil yang sama sebelum mencoba VueVPN agar route tidak berbenturan.

1. **Setup** — Salin build `artifacts/VueVPN.app` ke `/Applications`, buka, enable helper, berikan approval macOS, pastikan status helper enabled.
2. **Import** — Pilih file development yang benar. Periksa nama, username PIN, protokol, serta tiga route hasil import. Pastikan tidak ada data contoh yang otomatis dianggap tersambung.
3. **PIN** — Coba PIN salah: harus error tanpa menyimpan password. Coba PIN benar dengan remember: Connected hanya sesudah tunnel/route/DNS siap. Disconnect, connect lagi: tidak perlu input PIN. Gunakan Forget: koneksi berikutnya meminta PIN lagi.
4. **Split IPv4** — Pastikan resource development pada subnet pilihan bisa diakses. Periksa IP publik IPv4 tetap koneksi biasa. Periksa DNS internal dengan API resolver sistem/aplikasi; `dig` langsung tidak selalu mengikuti supplemental resolver macOS.
5. **Internal DNS disembunyikan** — Pastikan Overview dan Profile settings tidak menampilkan bagian Internal DNS, resolver, atau domain. Edit nama/rute profil yang memiliki DNS tersimpan: konfigurasi DNS sebelumnya harus tetap dipertahankan. Penanganan DNS dari server di backend tetap berjalan.
6. **Full IPv4** — Ubah ke All IPv4, pastikan reconnect profil tersebut dan periksa outgoing IPv4. IPv6 dan route lokal yang lebih spesifik tetap mengikuti macOS. VPN server harus mengizinkan forwarding/NAT internet untuk full tunnel berfungsi.
7. **Multi-profile** — Pakai profil development lain dengan subnet berbeda. Keduanya tetap aktif. Subnet/domain tumpang tindih dan full tunnel kedua harus ditolak. Disconnect salah satu: profil lain tetap berfungsi.
8. **Edit saat aktif** — Simpan perubahan subnet/DNS pada satu profil. Hanya profil itu reconnect; PIN sesi dapat dipakai lagi tanpa menyimpan ke disk.
9. **Menu bar** — Tutup window. Pilih profil dari menu bar, connect/disconnect, buka kembali window. Icon hijau bila minimal satu profil Connected, abu-abu bila tidak aktif, warna transisi saat connecting.
10. **Offline/sleep** — Matikan koneksi jaringan lalu pulihkan; sleep/wake. Status tidak tetap Connected ketika tunnel mati. Retry transport mengikuti batas lima percobaan; PIN/cert salah tidak retry terus.
11. **Cleanup** — Disconnect All dan Quit. Route serta resolver yang dibuat VueVPN hilang; koneksi normal tetap berfungsi. Buka kembali: tidak autoconnect. Untuk uji crash recovery, lakukan terpisah setelah jalur normal berhasil.
12. **Update helper otomatis** — Quit aplikasi lama tanpa disable helper. Ganti `/Applications/VueVPN.app` dengan artifact baru, lalu buka. Jika helper berbeda (termasuk versi lama tanpa fingerprint), tunggu status updating lalu enabled dan event sukses di Activity. Profil/PIN tersimpan tetap tersedia. Buka ulang build yang sama: tidak ada pembaruan helper berulang. Jika macOS meminta approval, berikan lewat Settings; aplikasi tidak terus mengulang registrasi.
13. **Update tertunda/gagal** — Ketika status update pending muncul dengan VPN aktif, koneksi harus tetap aktif dan koneksi baru ditunda. Disconnect semua atau gunakan **Disconnect all and update**: pembaruan dilanjutkan otomatis. Bila update gagal, pesan bertahan dan **Retry helper update** tersedia; jangan ada loop restart setiap polling. Helper yang disabled tetap disabled. Quit saat updating meminta menunggu sampai selesai.
14. **Registrasi hilang saat update** — Jika sebelumnya muncul not found setelah mengganti aplikasi, gunakan artifact terbaru tanpa disable helper. Status harus melanjutkan updating → enabled, tanpa perlu Retry lalu Enable. Registrasi yang gagal sementara dicoba maksimal tiga kali. Jika akhirnya perlu Retry, tombol itu harus menyelesaikan registrasi tanpa langkah Enable tambahan. Bundle tidak lengkap harus memberi pesan bahwa executable/plist hilang atau invalid, bukan mengulang registrasi terus.

15. **Dua split VPN setelah sleep lama** — Hubungkan dua profil Selected networks dengan subnet berbeda. Sleep selama 30–60 menit, lalu wake saat Wi-Fi masih reconnecting. Kedua sesi harus masuk Reconnecting; tunggu interface, alamat IPv4, dan gateway stabil sekitar 2 detik sebelum koneksi dicoba lagi. Setelah jaringan/server siap, periksa resource kedua profil dan internet biasa. Ulangi dengan Wi-Fi dimatikan ketika wake: sesi harus menunggu, bukan berhenti dengan `network_offline` atau kehabisan retry karena jaringan fisik belum siap.
16. **Disconnect selama pemulihan** — Saat kedua profil Reconnecting, Disconnect satu profil. Statusnya boleh Disconnecting selama route dibersihkan, tetapi status helper tetap bisa diperiksa dan profil kedua tetap bisa di-disconnect. Setelah Wi-Fi pulih, profil yang dibatalkan tidak boleh tersambung kembali. Quit, Remove profile, dan perubahan subnet menunggu cleanup; jika belum selesai dalam 30 detik, tindakan tersebut ditunda dengan pesan cleanup pending.
17. **Pemulihan komunikasi helper** — Jika XPC terputus, aplikasi menampilkan Recovering dan membuka ulang kanal komunikasi. Bila helper yang sebelumnya bekerja tetap tidak menjawab beberapa kali, aplikasi mencoba satu siklus stop/register/verifikasi otomatis. Sesi yang hilang karena helper harus direstart tidak ditampilkan Connected: hubungkan kembali profil setelah status Enabled. Jika masih gagal, gunakan Repair VPN helper / Retry helper update di aplikasi; tidak ada loop restart otomatis. Helper yang menunggu approval tetap menunggu persetujuan macOS.

18. **Statistik byte per profil** — Tanpa sesi aktif, area di bawah logo menampilkan `0/0`. Setelah connect, akses resource melalui VPN: angka kiri (IN) dan kanan (OUT) harus bertambah sekitar setiap 1 detik, misalnya `100B/100KB` atau `1.5MB/10MB`. Ini total byte transport VPN pada sesi tersebut, dengan 1 KB = 1.000 byte. Angka lebih besar daripada satuannya. Beralih di antara dua profil: setiap profil menampilkan totalnya sendiri. Total dipertahankan saat reconnect otomatis; setelah Disconnect tampilan kembali `0/0`, dan Connect baru memulai sesi baru. Pastikan keempat lingkaran kecil, termasuk dua di kiri, terlihat utuh di panel dan angka tidak bertabrakan dengan logo.

19. **Startup setelah mengganti build** — Quit VueVPN, ganti `/Applications/VueVPN.app` dengan artifact terbaru, lalu buka tanpa menekan Retry. Helper lama yang idle harus diganti otomatis. Respons awal yang terlambat atau fingerprint lama sesaat setelah registrasi tetap menampilkan Updating sampai verifikasi selesai. Kegagalan sementara saat unregister dicoba ulang maksimal dua kali; registrasi maksimal tiga kali, dengan observasi status sampai 45 detik per fase. Jika proses selesai sesudah timeout, aplikasi dapat melanjutkan registrasi/verifikasi tanpa klik Retry. Helper yang disabled atau menunggu persetujuan macOS tidak dipaksa aktif. Jika masih muncul kegagalan permanen, catat pesan lengkap Activity agar tahap yang gagal bisa diketahui.
20. **Lingkaran dan animasi jaringan** — Periksa keempat lingkaran kecil lebih besar dan tetap utuh di panel. Garis putus-putus lebih panjang dan bergerak jelas saat Connecting atau Connected; statistik IN/OUT tetap terpisah di bawah logo. Animasi menghormati pengaturan Reduce Motion macOS.
21. **Pindah Wi-Fi saat VPN aktif** — Hubungkan satu profil development dengan Selected networks, lalu pindah Wi-Fi A → B tanpa Disconnect. Sesi harus masuk Reconnecting, menunggu jaringan stabil sekitar 2 detik, membersihkan route lama, lalu terhubung lagi. Periksa resource development dan internet biasa. Ulangi B → A, kemudian dengan dua profil non-overlap dan mode All IPv4 secara terpisah. Jika tersedia, uji dua Wi-Fi dengan subnet/gateway/alamat DHCP yang sama: notifikasi link tetap harus memicu koneksi baru. Disconnect selama perpindahan harus membatalkan reconnect; helper tetap merespons. Setelah Disconnect selesai, coba profil yang sama di klien VPN lain; tidak semestinya tersisa route VueVPN menuju gateway lama.
22. **Retry cleanup setelah pergantian jaringan** — Jika cleanup sempat gagal, tunggu retry otomatis pada worker. Bila akhirnya masih Error, Connect harus mencoba membersihkan sesi lama sebelum membuat koneksi baru; Disconnect/Disconnect All mencoba cleanup lagi tanpa koneksi baru. Tidak perlu disable-enable helper untuk memulai retry. Error yang menetap tetap harus ditampilkan, bukan dianggap Disconnected. Saat startup, journal route yang belum bisa dibersihkan tidak membuat helper mati; percobaan Connect berikutnya melanjutkan cleanup sebelum mengizinkan route baru. Route milik klien lain harus tetap dipertahankan.
23. **Detail kegagalan OpenVPN** — Setelah memakai build/helper terbaru, coba ulang koneksi yang sebelumnya menampilkan `OpenVPN connection failed ().`. Jika gagal lagi, Overview dan Activity harus memuat kode yang tidak kosong serta detail error yang sudah disaring. Label kosong dari core menjadi `OPENVPN_ERROR`; jika core tidak memberikan deskripsi, pesan menjelaskan bahwa detail tidak tersedia. Catat pesan baru untuk diagnosis. Nilai credential, token, material profil inline, serta nilai dalam kutip/bracket disembunyikan; log mentah core tetap tidak diteruskan. Perubahan ini memperbaiki informasi error, bukan menyatakan penyebab koneksi sudah teratasi.

24. **Endpoint server IPv4** — Ganti aplikasi dengan artifact terbaru dan tunggu helper selesai update otomatis. Coba profil yang sebelumnya gagal dengan `remote_list_error: current remote server endpoint is undefined`. Alamat IP langsung sekarang dipakai tanpa resolusi DNS, termasuk setelah Disconnect/Connect dan pindah Wi-Fi. Pastikan resource VPN dapat diakses. Jika memakai profil hostname, alamat IPv4 dari DNS tetap harus bekerja; hasil kosong/tidak sesuai protokol menjadi `TRANSPORT_ERROR` dan mengikuti batas retry, bukan exception endpoint kosong. Verifikasi jaringan sebenarnya dilakukan pengguna; unit test hanya memakai hasil resolver sintetis.

25. **Upgrade native** — Quit versi lama, simpan salinan app lama jika ingin rollback, lalu ganti dengan package Swift/AppKit. Profil dan PIN yang sudah diingat tetap tersedia tanpa import ulang. Helper dengan fingerprint yang sama tidak perlu diganti. Tidak ada koneksi otomatis saat startup. Jangan menjalankan versi lama dan baru bersamaan.
26. **Window dan tampilan** — Periksa window awal 960×720 serta minimum 800×600, sidebar, Overview, Activity, App settings, editor, dialog PIN, hapus, error, dan toast. Cocokkan warna, font, icon double-V, empat circle, garis bergerak, serta slash statistik. Resize dan scroll editor berisi banyak route; tombol bawah harus tetap bisa dicapai. Periksa drag window, minimize/reopen, dan hanya satu instance.
27. **Input dan keyboard native** — Tab/Shift-Tab berpindah dalam dialog; Escape menutup kecuali operasi berlangsung. Return mengirim PIN atau menambah route sesuai field. Show/hide password mempertahankan isi dan fokus; selection teks berwarna netral. Teks statis tidak bisa dipilih. Connect/Disconnect langsung menampilkan status proses dan mencegah klik berulang. Coba nama profil panjang, error panjang, dan beberapa profil di sidebar.
28. **Menu dan animasi native** — Icon menu bar tidak mengecil, profil yang connected menyala, pilihan menu berubah sesuai state dan tidak bergeser ketika menu terbuka. Tutup window: VPN tetap berjalan. Buka kembali: statistik segar. Reduce Motion menghentikan animasi; Quit menunggu cleanup atau menampilkan error yang bisa ditindaklanjuti.

29. **Appearance** — Di App settings pilih Light, Dark, lalu System. Pilihan langsung mengubah seluruh window dan tetap tersimpan setelah Quit/buka ulang. Pada System, ubah appearance macOS saat window tampil, disembunyikan, dan saat dialog PIN/editor terbuka: tema ikut berubah tanpa menghapus draft, password, selection, atau scroll. Mode Light/Dark eksplisit tidak mengikuti perubahan macOS. Periksa input terfokus, placeholder, checkbox, error, statistik dan toast. VPN aktif tetap tersambung; tidak ada update helper atau reconnect akibat mengganti tema.
30. **Cursor hover** — Periksa navigasi, profil, tombol, icon, pilihan tema/routing, checkbox dan tombol show/hide PIN: cursor tangan hanya pada area kontrol yang aktif. Input menggunakan I-beam. Klik Connect lalu tahan mouse di tempat yang sama: setelah disabled cursor kembali panah. Coba enable kembali, scroll route/sidebar, resize window, serta buka/tutup modal; tidak boleh ada cursor tangan tertinggal atau area klik dari kontrol di belakang dialog.
31. **Energy / CPU** — Gunakan packaged Release, koneksikan satu profil dengan traffic ringan, dan tunggu stabil. Ukur rata-rata CPU VueVPN selama 60 detik pada Overview terlihat (target <5%), lalu window tertutup tombol merah atau sepenuhnya tertutup aplikasi lain (target <1%). Periksa juga Energy Impact dan WindowServer agar pekerjaan tidak sekadar berpindah proses. Label Significant Energy dan pengujian offscreen tidak menggantikan pengukuran ini. Ulangi dengan dua profil dan Low Power Mode; VPN/menu bar harus tetap bekerja. Pengukuran langsung ini belum dijalankan oleh agent.
32. **Retained animation** — Periksa garis, pulse saat Connecting, dan lingkaran pada Light/Dark serta ukuran 960×720/800×600. Scroll sampai ilustrasi keluar dari viewport, kembali, buka/tutup dialog, minimize/restore, Hide/Show, serta sleep/wake. Animasi kembali tanpa mengejar frame lama; statistik segera memakai nilai terbaru. Resize, pergantian tema, dan perpindahan layar Retina/non-Retina tidak boleh membalik/memburamkan panel atau mereset koneksi. Low Power Mode tetap beranimasi normal; Reduce Motion menampilkan ilustrasi statis. Draft, PIN, selection, scroll, cursor, dan hit target tombol harus tetap benar.

33. **Disconnect tanpa macet** — Dengan helper terbaru, uji Disconnect setelah sleep/wake, perpindahan Wi-Fi, dan dua profil selected-network aktif. Disconnect satu profil harus selesai tanpa menunggu callback statistik; profil lain tetap berfungsi. Pastikan route milik sesi yang terputus dibersihkan sebelum Connect berikutnya. Jika cleanup benar-benar tertahan lebih dari 30 detik, Overview/sidebar menampilkan **Disconnect stalled**, pesan error tampil di Overview/Activity, dan tombol/menu profil menjadi **Retry disconnect**. Sesi tetap dianggap aktif sehingga helper tidak diperbarui dan koneksi pengganti tidak dimulai sebelum cleanup selesai. Retry tidak merestart helper atau memutus profil lain. Unit test mencakup timeout dengan jam palsu dan reactor tanpa timer; reproduksi jaringan live tetap dilakukan pengguna.

34. **Profil username/password tanpa sertifikat klien** — Import profil development seperti Surfshark yang memakai `auth-user-pass`, CA dan `tls-auth` inline tanpa cert/key klien. Pastikan import berhasil dan file `.ovpn` asli tidak berubah. Isi username melalui **Edit profile**, lalu hubungkan dengan password yang benar; periksa akses dan Disconnect. Coba password salah, lalu pastikan tidak disimpan sebagai credential berhasil. Ulangi profil Pritunl dengan cert/key dan PIN untuk memastikan tetap berfungsi. Profil dengan hanya cert atau hanya key, serta profil yang secara eksplisit mewajibkan cert tetapi tidak memilikinya, harus ditolak.

Jika gagal, catat pesan di **Activity**, tindakan pemicu, mode routing, dan versi macOS. Jangan sertakan PIN, private key, atau keseluruhan `.ovpn` ke log/issue publik.

## System Stats — verifikasi langsung oleh pengguna

35. **Tanpa VPN/helper** — Buka CPU, RAM, SSD, Network saat VPN terputus dan helper disabled. Angka mesin tetap tersedia tanpa prompt administrator/Location. Data hardware yang tidak tersedia harus tertulis Unavailable.
36. **Menu bar/navigasi** — Pastikan urutan RAM, SSD, Network, CPU rapat tanpa teks terpotong: tepi kiri label kecil RAM/SSD/CPU dan seluruh persentasenya sejajar dalam tiap item; panah laju download ↓ dan upload ↑ rapat dengan nilainya, unit terbaca. Coba nilai 0%/9%/10%/40%/78%/85%/100%/Unavailable dan perpindahan B/s, KB/s, MB/s, GB/s; posisi tiap item harus tetap. Periksa Light/Dark macOS dan layar Retina/non-Retina. Klik tiap item saat window terbuka, tertutup, diminimize, dan tersembunyi; window lama kembali pada halaman yang tepat. Menu VPN dan koneksinya tetap berfungsi.
    Setelah CPU dan laju Network terisi, pindah cepat berulang CPU → RAM → SSD → Network → CPU, lalu sembunyikan/tutup/occlude window dan buka kembali dari item menu bar. Ulangi pada mode daya normal dan Low Power Mode. Nilai CPU dan download/upload tidak boleh sesaat berubah menjadi em dash hanya karena perpindahan halaman; sampel berikutnya tetap harus memperbarui nilainya. Saat data benar-benar belum tersedia, counter reset, atau antarmuka berubah, em dash tetap benar. Connectivity harus menandai periode Network tidak terlihat sebagai Not monitored.
37. **Layout/aksesibilitas** — Uji ukuran 960×720 dan 800×600, Light/Dark/System, scroll sidebar sampai semua profil dan Import terlihat, keyboard/VoiceOver, nama kontrol, serta target klik. Ikon CPU tampak sebagai chip, RAM sebagai modul memori, SSD sebagai drive, dan Network tetap globe; periksa ukuran kecil, selected, dan hover. Teks dan grafik harus terbaca; pindah halaman tidak memicu koneksi.
38. **CPU/RAM/SSD** — Bandingkan angka dan per-core E/P, load/uptime, pressure/swap, kapasitas dan I/O dengan utilitas sistem pada Mac ini. Periksa arah read/write dan label process I/O system-wide. Frekuensi serta reclaimable boleh Unavailable bila API tidak mendukungnya.
39. **Jaringan fisik** — Ganti Wi-Fi/Ethernet dan pilih antarmuka manual lalu otomatis. Pastikan nama/alamat/status benar, tidak ada penjumlahan tunnel VPN, total sesi terpisah per antarmuka dan pulih saat kembali, serta reset setelah Quit/buka ulang.
40. **Public IP** — Dengan dan tanpa VPN, hubungkan/putuskan/reconnect, ubah antarmuka cepat, gunakan Refresh, dan uji saat provider offline. IP lama harus stale lalu diperbarui untuk egress terkini; respons lama tidak boleh mengganti konteks baru. Tidak ada polling IP berkala.
41. **Connectivity** — Buka Network dan periksa target 1.1.1.1, latensi/jitter, tiga kegagalan, pemulihan, dan perubahan target. Tutup/occlude Network: probe berhenti dan riwayat menandai Not monitored. Status gagal hanya menyatakan target tak terjangkau.
42. **Cadence/sleep** — Bandingkan normal (~1s aggregate, ~3s proses) dan Low Power Mode (~2s, ~5s). SSD capacity ~30s. Coba sleep/display sleep dan bangun: tidak ada lonjakan rate atau burst mengejar tick. VPN animation tetap normal di Low Power Mode.
43. **Energi** — Pada packaged Release, ukur CPU VueVPN, subprocess/helper, WindowServer, Energy Impact, dan baterai untuk idle/menu-only, tiap halaman terlihat, Low Power Mode, dan traffic VPN. Bandingkan baseline sebelum Stats dengan beban, mode daya, layar, dan durasi sebanding. Target CPU lama pada butir 31 tetap pemeriksaan regresi; agent belum melakukan pengukuran langsung.
44. **Visibilitas dan perataan menu Stats** — Di CPU, RAM, SSD, dan Network, gunakan checkbox **Show in menu bar** secara terpisah lewat mouse dan keyboard/VoiceOver. Matikan satu per satu lalu semuanya: hanya item terkait dan ruangnya di menu bar yang hilang; angka, grafik, laju, total, dan detail di jendela tetap diperbarui. Nyalakan lagi: item kembali dengan nilai terkini, klik tetap membuka halaman yang sesuai, tanpa duplikasi atau pergeseran karena nilai berubah. Pada tiap item CPU/RAM/SSD, periksa tepi kiri label kecil sejajar dengan tepi kiri seluruh persentase saat nilainya satu, dua, dan tiga digit, serta saat tidak tersedia. Dua baris Network tetap rapat, sejajar di kiri, dan laju/satuannya terbaca. Periksa tampilan Light/Dark pada layar Retina dan non-Retina. Quit/buka ulang untuk memastikan pilihan tiap item tersimpan. Menu VPN tetap berfungsi.
45. **Enable monitoring** — Pada tiap halaman, matikan dan nyalakan monitoring saat halaman terbuka dan saat jendela tersembunyi. Halaman tetap dapat dipilih dan menyatakan Disabled; kontrol tampilan dinonaktifkan tanpa melupakan pilihan Show dan Label/Icon. Item tray terkait hilang dan kembali sesuai pilihan tersimpan. Periksa Collecting saat mulai kembali, tidak ada lonjakan laju setelah jeda, serta riwayat memiliki celah. Ulangi setelah Quit/buka ulang dengan kombinasi campuran dan semua monitoring mati; pengaturan lain dan menu VPN tetap berfungsi.
46. **Network saat monitoring mati** — Dengan VPN aktif dan tidak aktif, matikan Network monitoring lalu pindah halaman, sembunyikan jendela, ubah konteks VPN, dan lakukan sleep/wake. Pastikan tidak ada permintaan public-IP/probe Stats selama mati dan VPN tetap berjalan. Nyalakan kembali: antarmuka diperbarui, lookup public-IP segar dilakukan, probe hanya berjalan ketika halaman Network terlihat, dan total mempertahankan trafik yang diamati sebelum jeda tanpa menghitung trafik selama mati. Pengukuran jaringan/energi langsung ini dilakukan pengguna, bukan tes hostless.

### Stats menu-bar styles (user-run)

- Check adjacent RAM, SSD, Network, and CPU controls in Label, Icon, and mixed styles at 1x/2x and in light/dark menu bars. Confirm readable separation and independent click targets, including narrow and maximum readings, and that values changing do not shift the icons or neighboring items. macOS controls final status-bar placement; compare the actual gaps on the target Mac.

- In Icon style, verify CPU chip, RAM module, SSD drive, and Network globe have the same upright orientation as their sidebar counterparts. In both light and dark menu bars, their green must match the connected VueVPN tray logo exactly.
- Verify each metric is reachable and activatable with keyboard and VoiceOver, reports its own value and destination, and retains its tooltip. Confirm the Stats group moves as one macOS item (individual metric drag/reorder is no longer available), while the VPN item remains separate. Check partial and all-hidden configurations.
- On each Stats page select Label and Icon, including with Show in menu bar off. Confirm independent choices, immediate updates, latest values after hide/show, and persistence after Quit and restart.
- Check mixed styles and changing values: Icon percentages align by their visible right edge close to the larger green icon while the icon and item stay fixed; Label percentages retain their left alignment. Check single-, double-, and three-digit values and unavailable dashes. Network keeps both direction-labelled rate rows close to one fixed centered globe, including unit changes and maximum rates; check for clipping or overlap. Click each item and confirm its page opens; the VPN menu remains usable.
- In light and dark macOS menu-bar appearances, including a different explicitly selected window theme, inspect text contrast, green icons, sharpness at available display scales, spacing, highlighted/clicked states and system-controlled tray position. Close the window and reopen it from a metric, then compare with Quit and restart.
- Compare battery/energy impact under matched workloads using the existing energy procedure; offscreen tests do not measure live appearance or battery use.

### Stats realtime summaries

- At default and minimum window sizes, inspect CPU, RAM, SSD, and Network summaries in Light, Dark, and System. Check ring/bar/legend agreement, long names, readable units, and aligned checkboxes. Verify values in a summary are not repeated in lower detail rows, while history and distinct details remain.
- Check current readings against macOS, including SSD Available now, zero/unavailable network rates, and interface changes. Check monitoring off/on, window hide/show, scrolling, modal dialogs, Reduce Motion, sleep/wake, and Low Power Mode. Confirm history gaps and actual energy use on the target Mac.
